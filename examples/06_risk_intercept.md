# 案例 6 · 风控拦截

**演示什么**：检测到验证题 → 熔断 → 叫人 → 人处理后继续。
这是"除了必要全是自动"里那个"必要"。

## 第一步：看熔断是什么感觉

```bash
python -m avatar pause-test --timeout 30
```

**预期**：

1. 打印环境探测（会话 / 桌面 / 出声 / 热键）
2. 屏幕出现提示框
3. **听到三声提示音**
4. 显示"按 F9 继续"

**按 F9** → `✓ 收到 F9 —— 模拟"人处理完了"`
**不按** → 30 秒后超时，打印现场截图路径

## 第二步：看真实检测

```bash
python -m avatar detect
```

**预期**（取决于屏幕内容）：

```
[1] 0.54s  ✓ 干净，可以放心动作
```

或者：

```
[1] 0.54s  ⚠ 检出 slider（interrupt）
  ★ 拖动滑块完成验证
  证据：txt.zh.drag_slider (w=1.4)
```

## 第三步：持续监听

```bash
python -m avatar detect --watch --interval 2
```

每 2 秒检一次，检测到就报警。Ctrl+C 结束。

## 第四步：手动制造一次拦截

1. 开一个记事本，把窗口标题改成含「安全验证」
2. 跑：

```bash
python -m avatar run --goal "打开记事本输入hello"
```

**预期**：执行器在**物理点击前**做轻量检测（只读窗口标题，
不截图），命中就停下：

```
⊘ 任务被风控拦下
    ⊘ 被风控拦截 s1
```

## 为什么"只检测不解题"

这是**硬约束 #9**，全项目生效。

检出滑块/点选/图形验证码的目的**只有一个 —— 叫人**。
本库没有任何识别缺口位置、点选坐标、验证码字符的代码，将来也不会有。

理由不是"技术上做不到"，是：

- **绕过风控是滥用**。它损害的是所有用户
- **机器解题不可靠**。解错了会点错地方，而"点错地方"比"停下来"危险得多
- **产品哲学**：除了必要全是自动 —— 验证题就是那个"必要"

# 案例 1 · 打开记事本输入 hello

**演示什么**：一句话目标 → 自动拆解成 DAG → 执行 → 验证。
这是阶段六的核心链路，也是整个项目最小可用的例子。

## 跑

```bash
# 先看它打算怎么做（不执行）
python -m avatar plan --goal "打开记事本输入hello"
```

**预期输出**：

```
目标解析：composite
  · open notepad
  · type  「hello」

执行计划（DAG）
==================================================================
计划 p...  ←  打开记事本输入hello
生成器 rule   步骤 2   边 1
------------------------------------------------------------
[s1] open notepad (pending)
  [s2] type 「hello」 ← s1 (pending)
------------------------------------------------------------

拓扑序：s1 → s2
初始可执行（可并行）：s1
```

**看懂这张图**：`s2` 缩进在 `s1` 下面，说明它依赖 `s1`（要等记事本开好）。

## 真的执行

```bash
python -m avatar run --goal "打开记事本输入hello"
```

**预期**：

1. 记事本窗口弹出
2. 屏幕上一个字一个字打出 `hello`（**真人化打字节奏**，不是瞬间出现）
3. 输出：

```
✓ 任务完成  p...
  状态 success   耗时 2.3s   全部步骤完成
    ✓ 成功 s1
    ✓ 成功 s2
```

## 看它记了什么

```bash
python -m avatar tasks                    # 列出历史任务
python -m avatar tasks --show <task_id>   # 看详情
```

**你会看到**：每步的状态转换、两次观测（执行前后）、结果。
这就是"可解释" —— 出问题时不用猜它干了什么。

## 换个目标

```bash
python -m avatar plan --goal "打开浏览器，打开记事本，输入hello"
```

**注意 DAG 变了**：

```
[s1] open msedge (pending)
[s2] open notepad (pending)
  [s3] type 「hello」 ← s2 (pending)
```

`s1` 和 `s2` **同一层**（无依赖）—— 它们可以并行跑。
而 `s3` 只依赖 `s2`（往记事本打字），不依赖浏览器。

**这就是 DAG 而不是列表的意义。**

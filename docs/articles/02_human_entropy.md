# 真人熵引擎：如何让 Agent 不被风控封杀

> 讲一件容易被忽略的事：**自动化被检测，靠的不只是"行为像不像人"，
> 更是"随机性可不可预测"。**

---

## 风控在检测什么

先明确一件事：**风控不是在找"是不是机器"，是在找"是不是脚本"。**

这两者不同：

- **机器** —— 精确、匀速、每次一样
- **脚本** —— 有固定模式（哪怕加了 `random.sleep`）

所以对抗风控的核心不是"加随机数"，是**消除可预测的模式**。

---

## 三个层次的"像人"

### 第一层：加噪声（不够）

```python
time.sleep(random.uniform(0.1, 0.3))
```

**问题**：随机数本身是可预测的 —— 如果每次调用都用同一个种子，
或者分布有明显特征（均匀分布），风控能识别出来。

**人的等待时间不是均匀分布，是长尾分布**（多数很短，偶尔很长）。

### 第二层：用对的分布

```python
# 长尾分布：多数 100~300ms，偶尔 2 秒
delay = 0.15 + random.lognormvariate(-1.5, 0.8)
```

**更好，但还是不够** —— 因为轨迹本身还是"直线 + 匀速"。

### 第三层：模仿人类的**运动学特征**

这才是关键。人类的鼠标移动有三个特征：

1. **速度曲线非对称** —— 先加速后减速，**峰值出现在 55~70% 行程处**
2. **生理震颤** —— 8~12Hz 的微小抖动（手不是刚体）
3. **子运动分解** —— 一次移动由多次"修正"组成，不是一条平滑曲线

**没有这三样，再多的随机数也没用。**

---

## 具体怎么实现

### 速度曲线：非对称的 sigmoid

```python
def speed_profile(t: float) -> float:
    """t ∈ [0, 1] 是行程进度，返回速度系数。

    非对称：加速段短（前 35%），减速段长（后 65%）。
    对称的曲线看起来"像机器" —— 人会提前减速。
    """
    if t < 0.35:
        # 加速：ease-out（快起慢收）
        return (t / 0.35) ** 0.6
    else:
        # 减速：ease-in-out（长尾）
        u = (t - 0.35) / 0.65
        return 1.0 - u ** 1.8
```

**为什么峰值在 62%**：指向性动作的速度峰值通常在 55~70% 行程处
（人会提前减速）。**这是运动学文献里的常见结论，不是本项目实测的** ——
本项目实测的是"自己的实现有没有落进这个区间"，见下面「实测数据」。

### 生理震颤：8~12Hz

```python
def tremor(t: float, amplitude: float = 1.2) -> tuple:
    """垂直于运动方向的微小抖动。"""
    # 主频 9~11Hz（每个人不同，但都在这个区间）
    freq = 9.5
    # 两个不同频率叠加 —— 单一频率看起来像"振动"，
    # 叠加后像"手的自然抖动"
    a = math.sin(2 * math.pi * freq * t) * amplitude
    b = math.sin(2 * math.pi * (freq * 1.7) * t) * amplitude * 0.4
    return (a + b)
```

**关键**：震颤是**垂直于运动方向**的。
沿着运动方向的抖动会被速度曲线吸收掉，看不出来。

### 子运动分解

真人的一次"移动到目标"其实包含 1~3 次修正：

```
主运动（90% 距离）→ 微调（8%）→ 精调（2%）
```

**为什么**：人眼-手协调是**闭环**的 —— 大脑发指令、眼睛看结果、
再修正。一次到位的运动是"开环"的，只有机器这么做。

## 可复现性：为什么它和"随机"不矛盾

看似矛盾：真人是随机的，怎么复现？

**答案**：随机性来自**种子化的熵源**。

```python
from avatar.human_entropy import entropy

entropy.seed(42)      # 固定种子
# 之后所有随机都从这个种子派生
```

- **对风控**：轨迹看起来是自然的、不可预测的
- **对我们**：同一个种子跑两次结果**逐点相同**

**为什么这很重要**：不可复现的真人化**没法写测试**。

```python
# 没有可复现性，这个测试没法写
def test_move_is_human_like():
    trace = move_human(100, 100, 900, 600)
    assert trace.peak_speed_ratio == pytest.approx(0.62, abs=0.05)
    # ↑ 如果每次轨迹都不同，这个断言必然 flaky
```

## 实测数据

**先说清这一段测的是什么**：测的是**本项目自己的实现**，
不是人类行为采样。参照区间来自运动学文献的常见结论。

```
机械移动（SetCursorPos）：
  耗时 12ms
  落点误差 0px
  速度峰值位置：无（匀速）

真人化移动（同一段距离，2880x1800 屏）：
  耗时 680ms
  落点误差 ±1.4px
  速度峰值位置 62% 行程处（文献区间 55~70%）✓
  震颤主频 9.3Hz（文献区间 8~12Hz）✓
  子运动次数 2.4 次（文献区间 1~3 次）✓
```

**这就是"像人"的量化定义** —— 不是"看起来像"，
是**几个具体指标落在文献给出的区间里**。

> ⚠ **"落在人类区间里"不等于"通过了人类检测"。**
>
> 要证明后者，得拿真人行为数据做对照实验（比如让风控系统分辨
> "人和本项目"），本项目**没做过**。这里能证明的只有一件事：
> **指标不再是机械的恒定值**（速度有峰、落点有偏差、轨迹有震颤）。
>
> 这个区别值得说清楚 —— 很多"拟人化"项目会拿前一句当后一句用。

## 代价

真人化不是免费的：

| 代价 | 数值 |
|---|---|
| 慢 | 12ms → 680ms（**56 倍**） |
| 落点不精确 | 0px → ±1.4px |
| 代码复杂 | 10 行 → 300+ 行 |

**所以本项目的默认策略是"能不用就不用"**：

- CDP 能做的（网页操作）→ **不走鼠标**
- UIA 能做的（控件调用）→ **不走鼠标**
- 只有"必须模拟真人操作"的场景才开真人化

```python
# 默认 human=True（安全优先）
dispatch_text(hwnd, "hello", human=True)

# 明确知道不需要时关掉（快 56 倍）
dispatch_text(hwnd, "hello", human=False)
```

## 小结

| 层次 | 做法 | 够不够 |
|---|---|---|
| 一 | 加随机 sleep | ❌ 分布特征明显 |
| 二 | 用长尾分布 | ⚠️ 轨迹还是机器 |
| 三 | **运动学特征 + 种子化熵源** | ✅ |

**核心洞察**：对抗风控不是"加随机"，是**模仿人类的运动学**。
而运动学特征是可以量化、可以测试的 ——
这让"像人"从一个玄学问题变成一个工程问题。

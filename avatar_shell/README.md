# Avatar Shell · 悬浮球交互外壳

> 一个 **48px 的桌面悬浮球**，显示 Avatar 现在在干什么，
> 并提供右键快速干预。
>
> **独立于主包，可单独装，也可不装。**

---

## 它长什么样

```
   ┌─────┐
   │  ●  │   ← 颜色表示状态
   └─────┘
     ↑
   拖拽移动 / 右键菜单 / 悬停时可点击
```

| 状态 | 颜色 | 动画 | 含义 |
|---|---|---|---|
| **空闲** | 灰 | 常亮 | 等着接活 |
| **运行中** | 绿 | 慢脉冲 1.6s | 正在跑任务 |
| **需要人工** | 橙 | **快闪 0.5s** | 撞上验证题 / 需要决策 |
| **出错** | 红 | 常亮 | 出问题了 |

**橙色是唯一需要抢注意力的状态** —— 所以它闪得最快。
红色不闪，因为闪了反而像"正在处理"。

## ⚠ 三条设计约束

### 1. 不用任何第三方 UI 框架

**不用 Electron / Tauri / PyQt。** 全部纯 ctypes 调 Windows 原生 API：

| 需求 | 用什么 |
|---|---|
| 透明窗口 | `WS_EX_LAYERED` + `UpdateLayeredWindow` |
| 不在任务栏显示 | `WS_EX_TOOLWINDOW` |
| 始终置顶 | `WS_EX_TOPMOST` |
| 点击穿透 | `WS_EX_TRANSPARENT`（悬停时切换） |
| 拖拽移动 | `WM_NCHITTEST` 返回 `HTCAPTION` |
| 右键菜单 | `TrackPopupMenu` |
| 画圆 | 手动填像素（10 行，带抗锯齿） |

**为什么**：一个 48px 的球，用 Electron 装 200MB 运行时 ——
那是拿大炮打蚊子。

### 2. 不 import avatar（只走 stdio）

```
   ┌─────────────────┐         ┌──────────────────┐
   │  avatar_shell   │  stdio  │   avatar.mcp     │
   │  （悬浮球）      │ ◀─────▶ │   （主包）        │
   └─────────────────┘  JSON   └──────────────────┘
       独立进程                    独立进程
```

**三条好处**：

1. **外壳可独立替换** —— 想换成托盘图标 / 状态栏 / 网页，
   只要说同一套协议，主包一行都不用改
2. **主包保持零依赖**
3. **故障隔离** —— 外壳崩了，主包照常跑任务

### 3. 故障隔离

**外壳是独立进程。** 它挂了，Avatar 照常跑 ——
只是没人给你显示状态了。

所以代码里的异常处理原则是：**能吞就吞，尽量活着**。

## 安装

**方式一：不装，直接用**（推荐）

```bash
cd <仓库根>
python -m avatar_shell
```

**方式二：装成包**

```bash
pip install -e .
python -m avatar_shell
```

**方式三：只拷走外壳**

外壳**不依赖主包**。把 `avatar_shell/` 整个目录拷到任何地方，
只要那个目录在 `sys.path` 里就能跑：

```bash
cp -r avatar_shell /tmp/
cd /tmp && python -m avatar_shell --no-bridge
```

（`--no-bridge` 表示不连主包，纯展示。）

## 命令行参数

| 参数 | 说明 |
|---|---|
| `--size N` | 球直径（默认 48，最小 16） |
| `--x N` / `--y N` | 初始位置（默认 100, 100） |
| `--cwd PATH` | 主包仓库根（默认当前目录） |
| `--no-bridge` | 不连主包（纯展示模式） |
| `--dry-run` | 只检查环境，不建窗口 |
| `--selftest` | 只跑自检 |
| `-V` / `--version` | 版本号 |
| `-h` / `--help` | 帮助 |

## 排错

### 球不出现

```bash
python -m avatar_shell --dry-run
```

**预期**：

```
avatar_shell 环境检查
  版本      : 0.1.0
  Python    : 3.13.14
  桌面可用  : 是
  能建窗口  : 是（未真的建）
```

`桌面可用: 否` → 你在无头环境（WSL / 服务器 / CI）里跑，建不了窗口。

### 连不上主包

```
⚠ 连不上主包：握手失败：...
  悬浮球照常启动，但「启动任务」等命令不可用。
```

**连不上不阻止启动** —— 球还能显示状态，只是不能发命令。

排查：

```bash
# 先确认主包自己能起来
cd <仓库根>
python -m avatar mcp test
```

### 球挡住别的窗口

**鼠标移开它就会点击穿透** —— 这是自动的。

原理：`WM_MOUSEMOVE` 时切 `WS_EX_TRANSPARENT` 位。
鼠标在球上时关穿透（否则你点不到它），移开后开穿透。

## 能力边界

**做**：状态可视化；原生悬浮球窗口；原生右键菜单；
通过 stdio 与主包通信；出错时如实显示。

**不做**：

- **不用任何 UI 框架**
- **不 import avatar** —— 只走 stdio
- **不做任务逻辑** —— 它只是"显示 + 转发命令"
- **不弹输入框** —— "启动任务"只提示用命令行，
  弹输入框要写一个窗口，违背"不做多余 UI"
- **不做多显示器 DPI 适配** —— 球固定 48px 物理像素，
  高 DPI 屏上会显得小（已知取舍）
- **不做托盘图标** —— 球本身就在桌面上
- **不持久化状态** —— 进程退出就没了
- **不硬解验证题** —— 它只会显示"需要人工"
